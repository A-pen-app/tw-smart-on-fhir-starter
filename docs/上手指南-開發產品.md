# 上手指南：從零開發一個 SMART on FHIR 產品

> 對象：要做出「可以實際使用、之後可能上架」的產品的開發者。
> 只想先懂概念，請看 `00-入門簡介.md`。
> **本指南第 ③～⑥ 步的可執行版本在 `../smart-vitals-demo/`**（血壓/體重/BMI/心跳趨勢圖，已在沙盒實測）。
> 標示 ✅ 的是我們在 THAS 沙盒實測過的；標示 ⚠️ 的是**沒實測**，來自規格或推論，動手前請自行確認。

---

## 全流程一覽

```
 ① 定義產品      ② 準備環境     ③ 跑通最小 App    ④ 讀懂資料
 (做給誰、要什麼資料) → (工具、沙盒) → (登入、拿到 token) → (查詢、TW Core)
                                                         │
 ⑧ 上架與對接    ⑦ 部署        ⑥ 測試與安全      ⑤ 做出功能
 (市集、醫院)  ← (HTTPS、網址) ← (權限、錯誤處理)  ← (畫面、邏輯)
```

每一步都有「做什麼」、「怎麼做」、「做完的標準」。

## ① 定義產品：先回答四個問題

在寫任何程式前，先決定：

| 問題 | 為什麼重要 | 範例 |
|---|---|---|
| **給誰用？** 醫師、病人、還是後台系統 | 決定啟動方式與權限 | 醫師 |
| **在哪裡打開？** 嵌在病歷系統裡，還是獨立網站 | 決定用 EHR Launch 還是 Standalone | 嵌在病歷系統 |
| **需要哪些資料？** | 決定 scope 與是否符合 TW Core | Observation（HbA1c、血糖） |
| **只讀還是要寫回？** | 寫入的權限與審查要求高很多 | 只讀 |

**啟動方式怎麼選：**

| | EHR Launch | Standalone Launch |
|---|---|---|
| 適合 | 醫師在看診時使用，病人由病歷系統帶入 | 病人自己使用，或獨立工具 |
| 病人怎麼決定 | 病歷系統決定 | App 讓使用者登入後選 |
| scope 寫法 | `launch ...` | `launch/patient ...` |
| 建議 | **臨床產品優先** | 原型與病人端 |

**資料需求怎麼查：**
- 看 `可用資料清單.md`，確認資料在 TW Core 有沒有對應的 Profile。
- 列出「必要資料」與「有就更好的資料」，以免因為資料不齊而產品不能用。

**做完的標準：** 一頁文件，寫著使用者、啟動方式、所需資源（如 `Observation`、`Condition`）、讀或寫。

## ③ 跑通最小 App（Standalone）

目標：先把「登入 → 拿 token → 讀到一筆資料」這條路走通，後面才有基礎。

**1. 建立資料夾與兩個檔案**（範例在 `smart-poc/`）

`launch.html`

```html
<script src="https://cdn.jsdelivr.net/npm/fhirclient@2.6.3/build/fhir-client.js"></script>
<script>
  FHIR.oauth2.authorize({
    clientId: "my-app",                         // 自取
    scope: "launch/patient patient/Observation.read patient/Patient.read openid fhirUser",   // ✅ 沙盒可授予
    redirectUri: "index.html",
    iss: "https://thas.mohw.gov.tw/v/r4/fhir",
    launch: "e30"                               // 沙盒 Standalone 必填 ✅
  });
</script>
```

`index.html`

```html
<script src="https://cdn.jsdelivr.net/npm/fhirclient@2.6.3/build/fhir-client.js"></script>
<script>
  FHIR.oauth2.ready().then(async client => {
    const patient = await client.patient.read();
    console.log(patient);
  });
</script>
```

**2. 啟動**

```bash
python3 -m http.server 8080
```

**3. 走一遍**：打開 `http://localhost:8080/launch.html` → 選醫師（密碼已預填，直接 Login）→ 選病人 → 回到 App。

**常見錯誤：**

| 現象 | 原因 | 解法 |
|---|---|---|
| 授權端點回 400 `Invalid launch options` | 沒帶 `launch` | 加 `launch: "e30"` ✅ |
| `ready()` 出錯，找不到 state | 直接打開 `index.html`，沒經過 `launch.html` | 一律從 `launch.html` 開始 |
| 重新整理後失敗 | 授權 `code` 只能用一次 | 回到 `launch.html` 重新來 |
| 從 `file://` 打開失敗 | 需要 http 網址 | 用 `http.server` |

**做完的標準：** console 印出病人 JSON。

## ④ 讀懂資料：查詢與 TW Core

**FHIR 查詢就是網址：**

```
GET [base]/Observation?patient=3539&code=http://loinc.org|8480-6&_sort=-date&_count=10
```

| 參數 | 意思 |
|---|---|
| `patient=` | 只查這位病人 |
| `code=系統\|代碼` | 用代碼系統篩選（如 LOINC） |
| `_sort=-date` | 依日期新到舊 |
| `_count=` | 每頁筆數 |
| `_summary=count` | 只回筆數 |

**在 App 裡查（fhirclient）：**

```js
const obs = await client.patient.request(
  "Observation?code=http://loinc.org|29463-7&_sort=-date&_count=100",
  { pageLimit: 0, flat: true }   // pageLimit:0 = 抓完所有分頁；flat:true = 回傳資源陣列而非 Bundle
);
```

**三個一定要處理的資料現象：**

1. **分頁**：回傳是 Bundle，結果超過 `_count` 會有 `next` 連結。`fhirclient` **預設只抓第一頁**；`flat: true` 只是把結果攤平成陣列，**不會**抓更多頁，要抓全部必須加 `pageLimit: 0`。✅ 實測：同一個查詢，只用 `flat` 得 5 筆，加 `pageLimit: 0` 得 99 筆（等於總數）。
2. **欄位可能缺**：例如有些 Observation 沒有 `subject`、有的用 `valueQuantity` 有的用 `valueString`。程式裡要用 `?.` 保護，不要假設欄位存在。
3. **代碼可能不只一種**：同一個檢驗，不同醫院可能用 LOINC、也可能用院內碼。要處理 `code.coding[]` 是陣列。

**TW Core 要看什麼（以你要用的資源為主）：**

1. 打開 `twcore-ig/package/package/StructureDefinition-TWCore<資源名>.json`，或線上 IG：<https://twcore.mohw.gov.tw/ig/twcore/>。
2. 看三件事：**必填欄位**（`min = 1`）、**代碼綁定**（哪些 ValueSet）、**Must Support** 的欄位。
3. 對照 `twcore-ig/examples/` 的範例資源，看真實的資料長怎樣。

**注意 ✅：沙盒的資料是美式 Synthea，不一定符合 TW Core。** 想確認自己的 App 能讀懂台灣格式，要拿 `twcore-ig/examples/` 的範例資料另外測。

**做完的標準：** 能列出病人 3539 最近 10 筆你要的資料，並知道它欄位缺不缺。

## ⑤ 做出功能

到這裡就是一般網頁開發。建議做法：

**1. 分層：把「取資料」和「畫畫面」分開**

```
fhir.js      ← 只負責查詢、轉成你自己的簡單物件
logic.js     ← 判斷、計算（例如異常值判斷）
ui.js        ← 畫面
```

好處：之後換病歷系統、資料格式不同時，只改 `fhir.js`。

**2. 先轉成自己的資料格式**（完整版與單元測試見 `smart-vitals-demo/src/logic.js`）

```js
// 簡單的數值型 Observation → 你的格式
function toPoint(o) {
  return {
    date: o.effectiveDateTime,
    value: o.valueQuantity?.value,
    unit: o.valueQuantity?.unit,
  };
}
```

真實資料比這個複雜，範例專案處理了這些（都是沙盒裡真的遇到的）：

| 現象 | 做法 |
|---|---|
| 血壓有**兩種代碼**（`55284-4` 與 `85354-9`） | 查詢一次帶兩個代碼：`code=系統\|代碼1,系統\|代碼2` |
| 收縮壓/舒張壓在 `component[]`，順序不保證 | 用 LOINC 代碼（8480-6 / 8462-4）找，不要用 `component[0]` |
| 沒有數值、日期壞掉、`entered-in-error` | 轉換時丟掉，不拋例外 |
| 病人沒有這項資料、或單一查詢失敗 | 各區塊獨立處理（`Promise.allSettled`），一個失敗不影響其他 |

**3. 三種狀態都要做：** 載入中、沒有資料、出錯。醫療資料常常不齊，「沒有資料」是常態。

**4. 用的是 EHR 情境：** 從 `client.patient.id`、`client.encounter.id` 取得目前病人與就診，不要讓使用者自己輸入病人 ID。

**5. 若要用 EHR Launch**（臨床產品建議）：
- 建立 `ehr-launch.html`，scope 用 `launch`（不是 `launch/patient`），**不需要**帶 `iss` 與 `launch`，`fhirclient` 會從網址讀 ✅。
- 到 `https://thas.mohw.gov.tw/smart/sandbox` → 選「EHR Launch」→ 填你的 Launch URL → 立即測試 ✅。
- 範例：`smart-poc/ehr-launch.html`。

**6. 若要寫入資料：**
- 需要 `patient/Observation.write`（v1）或 `patient/Observation.cud`（v2）之類的權限。
- 沙盒會讓你寫，但**真實醫院不會這麼寬鬆**，且寫入的審查更嚴 ⚠️。
- 寫入的資料要符合 TW Core 的 Profile，建議先用 FHIR validator 驗證：<https://validator.fhir.org/>。

**做完的標準：** 功能在沙盒的多位病人上都能正常呈現，包含資料缺少的病人。

## ⑥ 測試與安全

**1. 權限：最小化申請**

| 不好 | 好 |
|---|---|
| `patient/*.read` | `patient/Observation.read patient/Patient.read` |
| `user/*.write` | 沒有需要就不要 |

**⚠️ 特別注意 ✅：沙盒不會檢查權限**（不帶 token 也能讀寫、能讀其他病人）。
所以沙盒測試通過不代表權限設定正確。請自己做這三件事：
- 在程式裡**只讀取 context 內的病人**。
- 逐一列出程式用到的資源，確認 scope 有涵蓋且沒多要。
- 之後連到真實系統時，先用最小權限測，不夠再加。

**2. Token 的處理**
- Access token 有效 3600 秒 ✅。要長時間使用就加 `offline_access` 取得 refresh token ✅，`fhirclient` 會自動更新。
- 不要把 token 印在 log、放進網址、或存進 localStorage 以外的地方（`fhirclient` 預設放 sessionStorage）。
- 純前端 App 是 public client，**不能**放 client secret。

**3. 個資**
- 不要把真實病人資料放進沙盒、範例、截圖、或 Git。
- 前端 App 盡量「零儲存」：資料只在畫面顯示，不寫進自己的資料庫。要儲存就要另外處理個資法。
- 錯誤訊息與 log 不要包含病人姓名或 ID。

**4. 測試清單**

| 項目 | 怎麼測 |
|---|---|
| 正常病人 | 3539（資料多） |
| 資料很少的病人 | 換一位；或搜尋 `TWIDIR` 開頭的病人 |
| 該資料完全不存在 | 確認顯示「沒有資料」而非錯誤 |
| Token 過期 | 等超過 1 小時，或手動改壞 token |
| 使用者按上一頁或重新整理 | 應能回到可用狀態 |
| 網路中斷 | 出現錯誤訊息，不是空白畫面 |
| TW Core 格式資料 | 用 `twcore-ig/examples/` 的範例測 |

**做完的標準：** 上面清單全部通過。

## ⑦ 部署

**要做的事：**

1. 把靜態網頁放到有 **HTTPS** 的網址（例如 Cloudflare Pages、Netlify、Vercel、GitHub Pages）⚠️。真實的授權伺服器通常要求 HTTPS，`localhost` 只是開發時的例外。
2. 把 `redirectUri` 與 Launch URL 改成正式網址。
3. 若用 CDN 載入 `fhirclient`，**釘死版本**（本專案用 `fhirclient@2.6.3`，是 2.x 最後一版），不要用浮動的 `@2`，以免某天更新後壞掉。最新的 3.0.0 我們沒測過。
4. 確認頁面能在醫院系統的 iframe 內載入。EHR Launch 常是內嵌的，所以**不能**設定 `X-Frame-Options: DENY`，要允許被嵌入 ⚠️。

**⚠️ 沒實測：** 正式環境是否要預先登記 `redirect_uri`、`client_id`。沙盒不需要，但真實醫院通常要，這部分要向對方確認。

**做完的標準：** 用正式網址在沙盒跑完整流程。

## ⑧ 上架與對接

### A. 上架到 THAS Marketplace

流程（來自 THAS 網站）：

```
Sandbox 測試 → 填「提案表」 → 資訊處審查 → 上架
```

| 你要準備的 | 說明 |
|---|---|
| App 說明 | 用途、對象、使用情境 |
| 使用的 FHIR 資源與術語值集 | 對應 TW Core 的哪些 Profile |
| Demo 網址 | 可供評審實際操作 |
| 通過沙盒驗測 | 符合 OAuth 2.0 + OpenID Connect |
| 聯絡人資訊與系統展示 | 審查項目 |

**現況：**
- 提案需要**登入會員**。
- **公開提案預計 2026 年開放**；目前是「臺灣 50」徵案的第一波。開放時程請向支援中心確認。
- 上架後的醫療 AI 需向「臨床 AI 註冊網頁」註冊並定期回報效能。
- 116 年後市集轉為商業營運，會有付費驗證與上架費。

**先做的事：** 寄信 medstandard@itri.org.tw 或電話 (02) 8590-6347，問（1）公開提案的時程；（2）提案表範本；（3）沙盒驗測的標準。回覆約 6 個工作天。

### B. 對接真實醫院

沙盒只是測試。要在醫院裡用，需要：

1. 與該院資訊室洽談，取得他們的 FHIR Server 與授權端點。
2. 看對方的 CapabilityStatement（`<base>/metadata`）確認支援的資源與搜尋參數。
3. 向對方登記你的 App（`client_id`、`redirect_uri`）⚠️。
4. 在對方的測試環境驗證，再上正式。
5. 資安與個資審查（各院流程不同）。

**產品規劃的提醒：** 每家醫院支援的資源、代碼、欄位都可能不同，所以第 ⑤ 步的「資料轉換層」要好好做。
