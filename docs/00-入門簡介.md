# 給新手的簡介：臺灣 SMART on FHIR 是什麼、怎麼做

> 不需要醫療或資訊背景也能看懂。想看細節請翻同資料夾的 `README.md`。
> 本文的操作步驟都已在 2026-09-24 實際跑通（見最後一節）。

---

## 1. 一句話說明

**把醫院的病歷系統想成「手機」，SMART 就是「App Store 的規則」。**
照這套規則寫出來的小工具，可以裝在不同醫院的系統裡，直接讀到該病人的資料，不用每家醫院重寫一次。

---

## 2. 為什麼需要它？

過去每家醫院的電子病歷都是自己開發的，資料格式各不相同：

- 想做一個「血糖趨勢圖」小工具，要跟 10 家醫院各談一次、各寫一套介接程式。
- 病人轉院，資料還要靠光碟或紙本。

衛福部的解法是訂三個統一標準：

| 統一什麼 | 標準名稱 | 用手機來比喻 |
|---|---|---|
| **資料長什麼樣子** | FHIR（+ 台灣版 TW Core IG） | 大家都用同一種插頭規格 |
| **規則怎麼寫** | CQL（健保規則等） | 大家都用同一種語言寫遊戲規則 |
| **小工具怎麼裝** | SMART | 大家都遵守同一個 App Store 規範 |

**我們要做的實驗性應用，就是第三層：一個 SMART App。**

---

## 3. 整體架構（五個角色）

```
   ┌──────────────┐        ① 使用者打開 App
   │   使用者      │ ─────────────────────────────┐
   │ (醫師/病人)   │                               ▼
   └──────────────┘                      ┌──────────────────┐
          ▲                              │   你的 SMART App  │  ← 我們要開發的部分
          │ ⑥ 顯示結果                    │ (一個網頁程式)     │
          └──────────────────────────────┤                  │
                                         └───┬──────────▲───┘
                       ② 「我想看資料，      │          │ ⑤ 用 token 讀資料
                          請問可以嗎？」     │          │   （拿回 JSON）
                                             ▼          │
                                ┌──────────────────┐    │
                                │  授權伺服器        │    │
                                │ (負責登入與發通行證)│    │
                                └───┬──────────────┘    │
                       ③ 使用者登入，│                   │
                          選病人、同意 │ ④ 發給 App        │
                                     ▼   一張「通行證」   │
                                (access token)          │
                                         ┌──────────────┴───┐
                                         │  FHIR 伺服器       │
                                         │ (真正存病歷資料的地方)│
                                         └──────────────────┘
```

用白話說：

1. **SMART App**：我們寫的網頁小工具，例如「檢驗數值一覽」。
2. **FHIR 伺服器**：存病歷資料的倉庫。它只認「通行證」，沒有通行證不給資料。
3. **授權伺服器**：像櫃檯。負責確認「你是誰」，並在使用者同意後，發一張限定範圍的通行證給 App。
4. **通行證（token）**：上面寫著「這個 App 只能看這位病人的資料、只能讀不能改」。到期就失效。
5. **使用者**：在授權時登入、選病人並同意。

這套「通行證」機制的標準名稱是 OAuth 2.0，登入身分則用 OpenID Connect。你不需要自己實作它，用現成函式庫（`fhirclient.js`）就好。

---

## 4. 什麼是 FHIR 資料？

FHIR 把病歷拆成很多「資源（Resource）」，每一種像一張表格，以 JSON 格式傳輸：

| 資源 | 放什麼 |
|---|---|
| Patient | 病人基本資料 |
| Observation | 檢驗值、生命徵象（血糖、血壓…） |
| Condition | 診斷 |
| MedicationRequest | 用藥醫囑 |
| Encounter | 一次就診 |

App 要資料就是打一個網址，例如：

```
GET https://thas.mohw.gov.tw/v/r4/fhir/Observation?patient=<病人ID>&_count=5
```

**TW Core IG** 是台灣版的「填表說明」：規定台灣的病歷該用哪些欄位、哪些代碼。我們的 App 要能讀懂它，才算「台灣相容」。

---

## 5. 兩種啟動方式

| 方式 | 說明 | 比喻 |
|---|---|---|
| **EHR Launch** | 醫師在病歷系統裡點一個按鈕，App 直接開啟，已知道是哪位病人 | 在 LINE 裡點小程式 |
| **Standalone Launch** | App 自己開啟（自己的網址），再去要求登入並選病人 | 直接開網站，再用 LINE 登入 |

台灣沙盒兩種都支援。**做實驗建議先從 Standalone 開始**，不需要有病歷系統就能測。

---

## 6. 實作步驟（從零到跑起來）

### 步驟 0：準備
- 一個文字編輯器、一個瀏覽器、Python 或 Node（用來在本機開網頁）。
- 不需要註冊帳號，也不需要申請金鑰。

### 步驟 1：了解測試環境
台灣的官方測試環境（沙盒）：

| 項目 | 網址 |
|---|---|
| 測試用 FHIR 伺服器 | `https://thas.mohw.gov.tw/v/r4/fhir` |
| 登入/授權 | `https://thas.mohw.gov.tw/v/r4/auth/authorize` |
| 領通行證 | `https://thas.mohw.gov.tw/v/r4/auth/token` |

裡面都是**合成的假資料**，可以放心試。

### 步驟 2：寫兩個網頁
用 `fhirclient.js` 函式庫，只需要兩個檔案（完整範例在 `smart-poc/`）：

**launch.html** — 負責「去櫃檯申請通行證」

```html
<script src="https://cdn.jsdelivr.net/npm/fhirclient@2/build/fhir-client.js"></script>
<script>
  FHIR.oauth2.authorize({
    clientId: "my-test-app",                      // 自取名字即可，沙盒不用註冊
    scope: "launch/patient patient/*.read openid fhirUser",  // 我要什麼權限
    redirectUri: "index.html",                     // 拿到通行證後回到哪一頁
    iss: "https://thas.mohw.gov.tw/v/r4/fhir",     // FHIR 伺服器位置
    launch: "e30"                                  // 沙盒的特殊要求（見下方注意事項）
  });
</script>
```

**index.html** — 拿到通行證後，讀資料並顯示

```html
<script src="https://cdn.jsdelivr.net/npm/fhirclient@2/build/fhir-client.js"></script>
<script>
  FHIR.oauth2.ready().then(async client => {
    const patient = await client.patient.read();           // 讀病人
    const obs = await client.patient.request("Observation?_count=5");  // 讀檢驗值
    // ……把 patient 和 obs 畫在畫面上
  });
</script>
```

### 步驟 3：在本機開起來

```bash
cd smart-poc
python3 -m http.server 8080
```

瀏覽器打開 `http://localhost:8080/launch.html`。

### 步驟 4：走一遍流程
1. 自動跳到台灣沙盒的登入頁 → 選一位醫師，直接按 Login（**任何密碼都可以**，這只是示範）。
2. 出現病人清單 → 點選一位病人。
3. 自動回到你的網頁 → 看到該病人資料。

**成功了！** 這就是一個最小的 SMART App。

### 步驟 5：換成你想做的功能
接下來就是一般的網頁開發：

- 想畫圖 → 用圖表函式庫把 Observation 畫成趨勢線。
- 想做提醒 → 判斷數值是否超標、標色。
- 想寫回資料 → 需要 `patient/*.write` 權限。沙盒可以寫入（已實測），但真實醫院會檢查權限。
- 想讓別人使用 → 見下一節「如何上架」。

---

## 7. 開發時要注意的幾件事

1. **只要你需要的權限。** 例如只讀檢驗值，就申請 `patient/Observation.read`，不要申請全部。這是隱私設計的核心原則，上架審查也會看。
2. **沙盒有個小特殊要求**：Standalone 啟動時要多帶 `launch: "e30"`（就是 `{}` 的編碼），否則會回 400 錯誤。這是我們實測發現的，官方頁面沒有寫。
3. **測試資料不一定完整**：例如我們一開始抽到的病人沒有檢驗值。建議用 ID 3539（Adán Portillo）測試，他有 99 筆 Observation；名單見 `沙盒驗證結果.md`。
4. **沙盒不會檢查權限**（連不帶 token 都能讀寫），所以測試通過不代表 scope 正確，要自己遵守最小權限。
5. **台灣相容是必要條件。** 上架要求 App 能讀懂 TW Core IG 的資料。可用 `twcore-ig/` 內的範例資源自我檢查。
6. **想要 refresh token（長時間登入）**，scope 要加 `offline_access`（已驗證）。
7. **不要把真實病患資料放進沙盒或範例。** 沙盒是公開共用的，任何人都能寫入。

---

## 8. 如何上架給別人用（官方市集）

流程（來自 THAS 網站）：

```
Sandbox 測試 → 填「提案表」 → 資訊處審查 → 上架到 Marketplace
```

- 提案需要**登入會員**。
- 公開提案**預計 2026 年開放**；目前第一波是「臺灣 50」徵案入選產品。
- 上架要求：符合 OAuth 2.0 與 OpenID Connect、支援 TW Core。
- 要接真實醫院資料，需自己與醫院洽談。
- 若是實驗性質，**先在沙盒跑通就已經足夠**，不必急著上架。

問題可以聯絡支援中心：medstandard@itri.org.tw（6 個工作天內回覆）。

## 9. 名詞小辭典

| 名詞 | 白話解釋 |
|---|---|
| **FHIR** | 病歷資料的統一格式與傳輸方式（讀作「fire」） |
| **Resource（資源）** | FHIR 裡的一種資料類型，像一張表 |
| **TW Core IG** | 台灣版的 FHIR 填表說明書 |
| **SMART** | 讓小工具能裝進不同醫院系統的規範 |
| **EHR** | 電子病歷系統（醫院用的系統） |
| **OAuth 2.0** | 「使用者同意後，發通行證給 App」的機制 |
| **OpenID Connect (OIDC)** | 在通行證機制上加入「確認你是誰」 |
| **Token（通行證）** | 有時效、有權限範圍的一串文字 |
| **Scope（權限範圍）** | 通行證上寫的「能做什麼」，如 `patient/Observation.read` |
| **Sandbox（沙盒）** | 只放假資料、可以放心亂試的測試環境 |
| **CQL** | 寫臨床規則的語言（如健保給付規則） |
| **CDS Hooks** | 在醫師操作時自動跳出提醒的機制 |
| **Marketplace** | 官方的 SMART App 市集（THAS） |

## 10. 我們實測過的結果（2026-09-24）

| 驗證項目 | 結果 |
|---|---|
| 沙盒 FHIR 伺服器可連線 | ✅ HAPI FHIR 8.6.0、R4 |
| 是否需要註冊 `client_id` | ✅ 不需要，可自取名稱 |
| `localhost` 可當 redirect | ✅ 可以 |
| Standalone launch 完整流程 | ✅ 登入 → 選病人 → 授權 → 取得 token → 讀取 Patient |
| Token 有效時間 | 3600 秒（1 小時） |
| 有無 ID Token（OIDC） | ✅ 有 |
| Refresh Token | ✅ scope 加 `offline_access` 就有，換新 token 也成功 |
| EHR Launch | ✅ 可用，token 內有 patient 與 encounter |
| 寫入資料 | ✅ 可寫，但沙盒不驗證權限 |
| `$everything` | ✅ 可用 |
| 不帶 `launch` 參數 | ❌ 回 400，需手動帶 `launch: "e30"` |

範例程式碼：`smart-poc/`。

## 11. 接下來可以做什麼

1. 把 `smart-poc/index.html` 改成漂亮的介面（例如檢驗值趨勢圖）。
2. 讀 `twcore-ig/examples/` 的範例，對照 TW Core 的欄位與代碼。
3. EHR Launch 已驗證可用，範例在 `smart-poc/ehr-launch.html`，步驟見 `沙盒驗證結果.md`。
4. 需要規則判斷時，再研究 CQL 與 CDS Hooks（見 `site-pages/rule-library_cql-service.txt`）。
5. 準備上架時，向支援中心確認提案時程與提案表格式。
