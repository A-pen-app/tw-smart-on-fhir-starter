## ⚠️ 重要發現：沙盒的 FHIR 伺服器不會檢查權限

| 測試 | 結果 |
|---|---|
| **完全不帶 token** 讀取 | 200（可讀） |
| **完全不帶 token** 新增資料 | 201（成功） |
| 只有 `patient/*.read` 的 token 新增資料 | 201（成功，本應被拒絕） |
| 用「為病人 3539 啟動」的 token 讀別的病人（3482） | 200（可讀，本應被限制） |
| 帶**格式錯誤的** token | 401（唯一會被擋的情況） |

**意義：**
- 沙盒的 FHIR 伺服器實際上是「開放」的，scope 與病人範圍都不會被強制執行。授權伺服器只負責發 token，資料伺服器不驗證權限。
- 所以**在沙盒測試通過，不代表 scope 設定正確**。若你的 App 多要了權限、或跨病人讀取，沙盒不會發現，但接到真實醫院的系統時可能被拒絕。
- 開發時請自己遵守最小權限原則，例如只申請 `patient/Observation.read`，並在程式裡確認只讀取 context 中的病人。
- 建議在測試時**刻意用不含某權限的 token 跑一次**，靠自己檢查 App 的行為，而不要依賴沙盒報錯。
- 這是共用的公開沙盒，任何人都可以寫入。請不要在裡面放任何真實資料，也不要留下測試垃圾。

## 各項細節

### EHR Launch 流程（已完整走通）
1. 打開 `https://thas.mohw.gov.tw/smart/sandbox`，選「EHR Launch」（另一個選項是 Provider Standalone Launch）。
2. 輸入你的 Launch URL（例如 `http://localhost:8080/ehr-launch.html`），按「立即測試」。
3. 沙盒開新視窗，導向 `你的網址?iss=https://thas.mohw.gov.tw/v/r4/fhir&launch=<代碼>`。
   代碼解碼後是一個陣列，例如 `[0,"","","AUTO",0,0,0,"","","","","","","",0,1,""]`，其中 `AUTO` 表示自動選病人。這是沙盒自己的格式，App 只要原封不動傳回授權伺服器即可，`fhirclient.js` 會自動處理。
4. 走完登入、選病人後回到 App，token 內有 `patient` 與 `encounter`。
5. EHR Launch 的 scope 用 `launch`（不是 `launch/patient`），病人由 EHR 提供。

### Standalone 與 EHR Launch 的差別（實測）
| | Standalone | EHR Launch |
|---|---|---|
| 觸發 | 自己打開 `launch.html` | 從沙盒頁面觸發 |
| 需手動帶 `launch: "e30"` | ✅ 需要 | ❌ 不需要（沙盒會給） |
| scope | `launch/patient ...` | `launch ...` |
| token 中的情境 | patient | patient + encounter |
